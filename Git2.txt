Tree :- Folders
Commit ->snapshot (Author ,Parent Commit ,Tree , Message, Timestamp) 1 commit points to 1 tree ,1 tree points to 1 blob
Tag:- named Version

1)Head = Head points to current branch (cat head)
2)config = Repository configuration (cat config) :- Repository settings,username,email,remote
3)objects = contains entire database (commits,trees,blob,tags) ,git stores everything here
4)refs = contains branches and tags 
5)logs = stores movement history 
6)hooks = contains automation scripts ,run tests before commit 
7)info = contains exclude file(ignore)


SHA Hash :- Git identifies everything using SHA.Unique identity , ,Integrity,fast lookup, no duplicates ,1 blob 


git status:- git compares working directory, staging area, repository it tells modified, deleted, new, staged, branch, merge conflicts 

git add . = Git copies the current version into the staging area.

How Rebase Works Internally

Suppose

master

A ----- B ----- C

Feature

A ----- B ----- D ----- E

Now master receives

F
G
master

A-B-C-F-G

Feature still

A-B-D-E

Now

git rebase master

Git DOES NOT move commits.

Instead

Step 1

Temporarily removes

D
E

Feature becomes

A-B

Step 2

Moves feature pointer

A-B-C-F-G

Step 3

Replays

D

then

E

Result

A-B-C-F-G-D'-E'

Notice

D'

E'

These are NEW commits.

Different hashes.
