Git stash:-
=================
Sometimes you have unfinished work.
Git stores your work temporarily.
It is used to check the code in other branch without committing

step1:- git stash  //temporary area
     :- git stash list
step2:- git checkout <branch_name> //branch switch
step3:- git checkout <previous_branch_name>  //back to previous branch
step4:- git stash pop  //to get the code back and it will be removed from stash area
come from stach area to current working directory:- git stash apply 
                                       Perticular:- git stash apply stash@{0}
                                       Perticular:- git stash pop stash@{0}

//To remove the stash area
git stash drop
git stash clear  //delete all
git stash drop stash@{1}

Git Rebase:-
==========
Moves commits.
Cleaner history.

git rebase main

no extra merge commit 
linear , cleaner, professional
copy commits delete old ones, create new commits - different commits new hashes old commits removed 
it is better than git merge 
with rebase = no multiple merge only commit 

Merge	                        Rebase
===================          =========================
Preserves history	         Rewrites history
Creates merge commit	     No merge commit
Safe	                     Dangerous if shared
Easy	                     Advanced
Default for teams	         Preferred before PR

Interactive Rebase
=====================
git rebase -i HEAD~5       //open last 5 commits  , we can change those last 5 commits 

pick = keep commit , reword = change commit message , edit = modify commit , drop = delete commit, squash = combine commits, fixup = combine without keeping message 

git rebase conflict:-
======================
git add .
git rebase --continue
git rebase --abort      //Everything returns to before the rebase.
git rebase --skip       //If you don't care about the conflicting commit , Git ignores that commit.

when to use rebase:-
====================
before pull request 
---------------------
git fetch origin 
git rebase origin/main

Merge combines histories and creates a merge commit while preserving the original commit graph. Rebase rewrites commit history by replaying commits on top of another branch, producing a clean linear history. Rebase should generally be used only on private branches, while merge is safer for shared branches because it doesn't rewrite history.
